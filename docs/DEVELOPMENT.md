# 开发与扩展约定

## 新功能放在哪里

- 新业务规则：放到 `src/main/modules/<模块名>`，不得写进 React 页面。
- 新界面：放到 `src/renderer/src/features/<模块名>`。
- 新 IPC：先在 `src/shared/ipc-channels.ts` 和 `contracts.ts` 定义，再分别实现主进程处理器和预加载桥方法。
- 新外部平台：实现 `Connector`，然后在 `ConnectorRegistry` 注册。
- 新 AI 服务：实现 `VisionNamingProvider`，任务流程只依赖接口，不依赖具体厂商 SDK。
- 新 Excel 引擎：实现 `SpreadsheetPort`，必须通过格式与公式回归测试。

## 禁止事项

- React 界面不得导入 `fs`、`path`、`electron` 或保存密钥。
- 不得在业务服务里直接弹文件选择框；文件选择由专门的桌面服务处理。
- 命名-公式不得覆盖；A 条码参考和国内命名表不得绕开“质检坐标计划、临时文件验证、覆盖前备份、同批次历史记录”直接写入。
- 不得绕开同系列重名、产品重码和公式完整性检查。
- 不得在一个连接器中判断另一个平台的业务逻辑。

## 完成一个模块的最低标准

1. 明确输入、输出和错误类型。
2. 关键规则至少有一个正常测试和一个异常测试。
3. UI 只显示真实状态，未配置接口不得显示“已连接”。
4. 写文件前生成任务工作副本；失败不留下半成品。
5. 日志不得包含机器人密钥、访问令牌或完整客户数据。

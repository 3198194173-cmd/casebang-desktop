# CASEBANG 软件主流程与页面重构

日期：2026-09-17  
目标：先统一业务逻辑、账号职责、文件流向和页面命名，再继续开发编码、核图与总表同步。

## 1. 唯一主流程

现有三个功能不是互相连续的三步，而是三种并列的上游建表入口：

- **新系列建表**：新系列裁图、命名、产品编码、生成与质检。
- **系列补产品**：在既有系列中增加产品或图案，复用历史系列与命名资料。
- **产品补机型**：为既有产品增加机型，依据物料总表匹配并生成新增记录。

任意一个入口完成后都产生一份“待建档工作簿”，然后进入同一个下游流程：

```text
新系列建表 ─┐
系列补产品 ─┼─→ 生成与质检通过 → 提交建档任务 → 建档处理 → 原建表人复核 → 合并总表 → 同步在线表格
产品补机型 ─┘
```

因此，界面不能再把“协同任务”和“物料建档”作为两个平级业务模块。协同只是任务传递机制，真正对用户有意义的下游入口只有一个：**建档任务**。

## 2. 两个账号的职责

### A：建表人

1. 从三个上游入口中选择一个完成建表。
2. 在生成与质检通过后点击“提交建档”。
3. 选择同企业的建档人 B。
4. 等待 B 完成编码和核图。
5. 接收 B 返回的新修订，查看差异。
6. 不通过时退回 B；通过后合并物料总表并同步钉钉在线表格。

### B：建档人

1. 在“建档任务”的“待我处理”中看到任务。
2. 接收任务并取得服务器保存的同一文件版本。
3. 完成物料编码与 69 码，两项先后不限。
4. 对照钉盘图档，逐项记录核对结论。
5. 在 Excel/WPS 修改工作簿后，将新修订上传服务器。
6. 所有必填项和图档核对通过后，提交给原建表人 A 复核。

账号属于整个软件，不属于某一个页面。登录后所有页面共用同一企业身份；退出登录也应全局生效。

首次登录前必须单选业务身份：**上游建表**或**下游建档**。选择会与钉钉账号绑定，不能靠退出后重新勾选来切换。页面隐藏只是体验层，中央服务还必须再次校验：上游只能提交、查看发出任务和复核；下游只能接收、处理和回传。需要更换职责时由管理员调整，不能让用户自行越权。

## 3. 文件真正的流向

```text
A 本机生成文件
  → 上传中央服务，形成修订 1
  → B 点击“接收并开始处理”
  → 软件自动建立本机工作副本并用 Excel/WPS 打开
  → B 保存修改，点击“提交处理结果”上传修订 2
  → A 打开修订 2，并与修订 1 对比
  → A 确认后合并总表
```

“能看到任务”不等于“文件互传完成”。完整互传至少要同时满足：

- A 上传后，软件为 B 建立的本机工作副本 SHA-256 与服务器修订一致。
- B 修改后可以上传新修订，不能只填写退回原因。
- A 能取得 B 的新修订并看到字段差异。
- 每次上传都记录提交人、时间、文件哈希、修订号和来源任务。
- 两个账号不能同时覆盖同一修订；过期页面提交时必须提示刷新。

## 4. 页面与导航

左侧导航只表达稳定业务入口：

- **工作台**
  - 业务总览
- **上游建表**
  - 新系列建表
  - 系列补产品
  - 产品补机型
- **任务中心**
  - 建档任务
- **资料与配置**
  - 基础数据
  - AI 与接口
- **系统**
  - 系统设置

不再在左侧同时出现“协同任务”和“物料建档”。旧工作簿手工导入只是测试与历史补录能力，应作为“建档任务”页面的次要按钮，不应成为主导航。

## 5. 建档任务页面

默认先显示任务列表，不先显示编码表单：

- **待我处理**：只对下游账号显示。
- **我发出的**：只对上游账号显示。
- **待我复核**：B 已完成、等待 A 确认的任务。
- **已完成**：已合并或已同步的任务。

点开一项任务后，根据当前账号的职责显示不同操作。

建档人 B 的任务详情：

1. 接收并开始处理
2. 编码处理
3. 图档核对
4. 提交复核

建表人 A 的任务详情：

1. 查看结果
2. 差异复核
3. 合并总表
4. 同步在线表格

系统连接状态、钉钉 Stream、服务器地址和接口权限只放在“系统设置”，不能成为业务步骤页签。

## 6. 页面命名规则

页面名称使用“对象 + 动作”，不使用开发术语或过长说明：

- 表格编码 → **新系列建表**
- 原有系列补充新产品编码 → **系列补产品**
- 原有产品补充新机型 → **产品补机型**
- 协同任务 + 物料建档 → **建档任务**
- 物料编码预检 → **检查物料码**
- 69 码来源 → **选择69码来源**
- 提交交接 → **选择接收人**
- 接入状态 → 移至 **系统设置**

说明文字可以保留完整业务含义，但菜单和按钮必须简短。

## 7. 当前真实完成度

已经完成：

- 全软件钉钉登录；登录前选择上游/下游，账号角色由服务器绑定并校验。
- 上游只显示建表与发出任务，下游只显示建档任务；接口同时阻止越权调用。
- A 手工导入工作簿并上传中央服务器。
- B 点击一次即可接收任务、自动建立本机工作副本并用 Excel/WPS 打开；不再出现手动“下载工作簿”。
- B 填写原因退回 A。
- 任务版本、组织边界、责任人权限和操作事件基础校验。

尚未完成：

- 三个上游生成完成页直接提交建档任务。
- B 上传修改后的新修订并返回 A。
- A 查看两版差异并复核。
- 正式物料码、69 码账本和并发发号。
- 钉盘图档检索、预览和核对证据。
- outbox 真实发送钉钉通知。
- 物料总表合并及钉钉在线表格写入、回读。

## 8. 下一轮开发顺序

1. 先把三个上游流程的生成结果接到统一“提交建档”入口。
2. 实现 B 保存工作副本后上传新修订，并验证文件哈希和任务版本。
3. 实现 A/B 两端的任务状态页签和 A→B→A 双账号实测。
4. 再开发物料码、69 码和图档核对，不提前展示尚未可用的正式按钮。
5. 最后接总表合并、钉钉在线表格和通知。

## 9. 双账号互传验收

测试必须使用两个不同钉钉账号，推荐两台电脑；单机切换账号只能作为补充测试。

1. A 登录时选择“上游建表”，B 登录时选择“下游建档”；服务器成员表中存在两条不同用户记录和对应角色。
2. A 完成一份小型测试工作簿并选择 B 提交。
3. B 的“待我处理”出现任务，点击“接收并开始处理”，软件自动打开工作副本并核对哈希。
4. B 接收任务、修改一个指定单元格、保存并上传为修订 2。
5. A 的“待我复核”出现同一任务，打开修订 2，能看到指定差异。
6. A 退回一次，B 修订后再次提交；任务始终只有一个，修订号递增。
7. A 最终通过后再进入测试总表合并；正式总表和在线表格在全流程通过前保持只读。

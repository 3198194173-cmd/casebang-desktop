# A 条码参考表系列码自动补全方案

## 目标

`A条码参考` 工作簿的 `系列名对应代码` 工作表中，A 列是全局唯一的系列码池。系统需要在不覆盖已有业务数据、不改变既有行位置的前提下：

1. 识别已使用系列码和空白预留系列码。
2. 为新系列分配第一个可用的预留系列码。
3. 当预留数量不足时，在后续空行的 A 列自动补码。
4. 将补码纳入现有的“编码预览 → 生成与质检 → 覆盖基础表 → 版本回滚”闭环。
5. 支持两位编码耗尽后扩展到 `A10`、`A11` 等三位及更长编码。

## 业务口径

系列码行分为三类：

- **已使用**：A 列有合法系列码，且 B/C/D 至少一列已有系列资料。
- **可用预留**：A 列有合法系列码，B/C/D 均为空。
- **待补充**：A 列为空，可由系统在写入计划中补充系列码。

无论 B/C/D 是否为空，只要 A 列已有合法代码，该代码都必须计入全局占用集合，不能再次生成。

建议把“保留 10 个可用系列码”定义为：本次使用的系列码之后仍有 10 个空白可用码。例如本次使用 `K1`，则应确保 `K2`、`K3`、`K4`、`K5`、`K6`、`K7`、`K8`、`K9`、`L0`、`L1` 共 10 个预留码存在。

如果采用“包含当前 K1 在内连续保留 10 格”的口径，则只需补到 `L0`。实现时预留数量应作为单一配置项，默认按“真正空闲 10 个”处理，避免口径混淆。

## 编码顺序

为了兼容现有数据并符合当前人工习惯，顺序定义为：

1. 第一阶段：`A0` 至 `Z9`。
2. 第二阶段：`A10` 至 `A99`，然后 `B10` 至 `B99`，依次到 `Z99`。
3. 第三阶段：`A100` 至 `A999`，然后按字母继续。
4. 后续按相同规则扩展。

关键边界：

- `I9 → J0`
- `K9 → L0`
- `Z9 → A10`
- `A99 → B10`
- `Z99 → A100`

系统只生成“一个大写英文字母 + 正整数”的编码，统一使用正则 `^[A-Z]\d+$`。历史表中若发现不符合规则的非空值，不自动改写，必须在质检中提示具体单元格。

## 唯一的数据链路

不能另建一套直接修改基础表的补码逻辑。补码必须使用现有业务流程的同一份写入计划：

1. **导入/基础资料预览**
   - 扫描 A 列全部非空代码。
   - 区分已使用、可用预留、重复、非法和断档。
   - 此阶段只分析，不直接改原文件。

2. **编码预览**
   - 优先选择第一个可用预留码。
   - 计算本次占用后剩余预留数量。
   - 生成需要补入 A 列的确切单元格地址和值。

3. **生成与质检**
   - 当前系列资料写入位置继续沿用现有质检工作簿中的地址。
   - 自动补码作为同一个工作簿写入计划的一部分显示，绿色标出真正会变化的 A 列单元格。
   - 质检校验唯一性、连续性、预留数量和目标地址是否锁定。

4. **覆盖基础表**
   - 只执行已经质检通过并锁定地址的写入计划。
   - 同一次覆盖同时写入当前系列资料和缺失的预留系列码。
   - 进入现有覆盖时间线，使用同一组备份和回滚记录。
   - 每次执行覆盖前重新读取最新的 A 条码参考基础表，重新校验占用、重复和预留数量；如果基础表在预览后发生过变化，则原计划失效，必须刷新质检预览后才能覆盖。
   - 覆盖成功后立即刷新基础资料缓存与表格预览，使新补充的系列码无需重启软件即可看到。

这样预览看到的位置、导出结果和覆盖基础表的位置完全一致，不会产生两套写入规则。

## 核心数据结构

编码预览结果增加统一的系列码计划：

```ts
interface SeriesCodePlan {
  selectedCode: string
  nextAvailableCode: string | null
  requiredReserveCount: number
  availableReserveCodes: string[]
  supplementWrites: Array<{
    sheetName: string
    address: string
    value: string
  }>
  duplicateCodes: Array<{ code: string; addresses: string[] }>
  invalidCells: Array<{ address: string; value: string }>
}
```

编码预览阶段只计算一次。后续生成、质检、导出和覆盖均消费该计划，不再各自重新推算。

## 填充规则

1. 找到 `系列名对应代码` 工作表及 A 列表头位置。
2. 按行扫描已有系列码，保留所有原值与行号。
3. 重复或非法代码存在时禁止进入覆盖，明确提示冲突单元格。
4. 新系列优先使用首个 B/C/D 为空的合法预留码。
5. 从当前序列末端继续生成，直到达到配置的空闲预留数量。
6. 只写 A 列空单元格，不覆盖 B/C/D、公式、图片或已有 A 列值。
7. 中间空行只有在前后代码能按规则唯一推导且不会冲突时才补；发现顺序异常时停止自动修补并进入质检提示。
8. 如果超出现有格式化行范围，复制最后一个系列码行的行高、边框、对齐和保护属性，再写入 A 列；不复制业务内容和图片。

## 前端调整

编码预览页显示：

- 本次使用：`K1`
- 当前可用预留：`8 / 10`
- 将自动补充：`L0、L1`
- 异常时显示重复代码或非法单元格地址，并禁用下一步。

生成与质检页的 A 条码参考表预览必须展示所有计划写入：

- 本次使用的系列码及中英文名称。
- 为保持预留数量而自动补入 A 列的系列码。
- 自动补码单元格使用与其他程序新增内容一致的绿色变化标记。
- 预览只展示计划，不修改基础表；只有用户点击“覆盖基础表”后才真正落盘。

基础资料页在覆盖成功后自动重新读取工作簿，因此补充后的代码会出现在完整表格预览和该次覆盖记录中。若该次覆盖被回滚，业务数据与同组自动补充的系列码一起恢复到覆盖前状态。

## 自动补充触发时机

每次生成 A 条码参考表覆盖计划时都执行一次预留检查，而不是只在首次导入时执行：

1. 读取当前最新基础表。
2. 扣除本次即将占用的预留码。
3. 计算覆盖完成后仍可使用的空闲系列码数量。
4. 数量不足时，把缺少的系列码加入本次质检预览及覆盖计划。
5. 数量已满足时不产生额外写入，也不把空白单元格错误标绿。

因此每运行并覆盖一次业务流程，系列码池都会自动向后补足；但未执行覆盖时不会改动原始基础表。

手动系列码输入由固定两位改为 `一个大写字母 + 至少一位数字`，移除当前的两字符截断。输入值统一转大写，但不静默修改格式错误。

## 代码改造范围

1. 新建唯一的系列码序列模块，提供 `parse`、`compare`、`next`、`range` 和合法性校验。
2. 修改编码预览构建器：A 列只要有合法代码就计入占用，不再要求名称列有值。
3. 修改工作簿生成器：把补充 A 列代码加入现有固定地址写入计划。
4. 修改共享契约：加入 `SeriesCodePlan`，让主进程与前端共用同一结果。
5. 修改前端输入限制、状态提示和质检信息。
6. 覆盖与回滚沿用当前基础表版本机制，不增加独立写表入口。

## 必测场景

- 已有 `K0`，预留为空：正确生成 `K1` 至目标预留数量。
- 已有并使用 `K1`：按配置补足后续空闲代码。
- A 列已有 `K2` 但名称为空：识别为预留，不能重复生成。
- `K9` 后正确生成 `L0`。
- `Z9` 后正确生成 `A10`。
- `A99` 后正确生成 `B10`。
- A 列出现重复代码：阻断覆盖并显示所有冲突地址。
- A 列出现非法代码：不改原值，阻断覆盖。
- 表内有中间空行：仅在顺序可以唯一推导时补齐。
- 补码后，预览、导出、覆盖基础表三者单元格地址和值完全一致。
- 覆盖后基础资料预览立即可见；整组覆盖可以按现有版本记录回滚。

## 实施顺序

1. 先落地统一序列算法和单元测试。
2. 修复系列码扫描与推荐逻辑。
3. 将预留补码接入同一生成写入计划。
4. 增加质检与前端提示。
5. 补充导出、覆盖、回滚集成测试。

# 物料编码规则与总表核验附录

日期：2026-09-16 · 对应[物料建档协同项目文档 1.1](MATERIAL_LIFECYCLE_PROJECT.md)。

用途：固定本轮用户确认规则、记录总表佐证及历史例外，供后续开发实现。仅修改文档，未修改 Excel、未生成正式号码。

## 1. 本次已确认规则

1. 手机物料编码末两位数字是机型码，不是末三位。
2. `A053 = A0 + 53`；`A057 = A0 + 57`；`AC57 = AC + 57`。
3. 69 码用自定义号还是网站取得的号码，由当前账号使用人决定，不按华为/非华为强制选择。
4. 物料编码与 69 码分开处理，先做哪一项都可以；最终交回原建表人前仍需两项均完成。
5. 以下 45 项机型映射由用户直接确认，可以用于初始字典。总表佐证缺失不否定已确认的新机型。

## 2. 核验资料与范围

总表：`表格文件/CASEBANG 物料名称汇总-260908（含建议零售价）.xlsx`。

- 遍历两张工作表，统计同时具有物料编码 C 和物料名称 D 的记录：`条码` 53,956 条，`出片壳` 104 条，共 54,060 条。这是本次扫描口径，不代表全部记录都是本规则适用的手机物料，也不代表去重后的唯一 SKU 数。
- 源文件的工作表尺寸元数据均显示 A1，但实际存在完整数据。只读分析时忽略错误尺寸边界后扫描实际单元格；后续导入器也不能看到 A1 就认定总表空白。
- 机型交叉验证主要限定 `C.K.BG/CA.AP/SA/HW` 且名称有 BG/CZ 产品码的手机物料，避免把支架或 Macbook 的末位号码误当手机机型。对三个未见记录的新华为码另查品牌和产品范围。
- 普通/银框按名称的明确框型后缀区分，并将相同系列、产品图案、机型的记录进行成对对照；只移除框型标签及无意义空白，不移除 Y/B/T 等其他款式信息。
- 全表还有非标准历史前缀、普通款非 A0/B0 的历史标识，均不自动纠正。本轮没有授权更改这些历史数据。

### 总表交叉验证结论

45 个机型码中，42 个在本次总表的相应手机物料中有佐证，部分名称与用户标准名采用不同显示形式；不能把“42 个有码记录”说成“全部名称逐字一致”。另 3 项为用户确认的新机型映射：HW 12、13、16，当前总表未找到对应 Mate 90 系列记录。

发现的历史显示形式：

- `47`：`iP16e/17e`，也有 `iP16e`。例如 `条码!C26614:D26614` 为组合适配名称。
- `74`：`iP18 Pro/17 Pro`，也有 `iP17 Pro`。组合名称示例 `条码!C26632:D26632`。
- `75`：`iP18 Pro Max/17 Pro Max`，也有 `iP17 Pro Max`。示例 `条码!C26638:D26638`。
- `95`：`Mate 70 Pro/Pro+`，另有带 HW 前缀的 `HW Mate 70 Pro`。
- `94`：总表可见 `HW Mate 70`，用户标准名为 `Mate 70`。
- `51`：总表为 `PX Max`，用户标准名为 `Pu X Max`；示例 `条码!C31539:D31539`。登记为同码的历史名称证据；展示名/别名合并策略需确认，不自动纠正文案。
- `15`：`HW PX View`，示例 `条码!C53099:D53099`。

实现约束：

- 按“品牌 + 适用产品范围 + 名称/确认别名”查字典，不仅按末两位全局反查唯一型号。
- 例如 `条码!C295:D295` 和 `C298:D298` 的苹果 Macbook 物料末两位分别是 12、16；它们不是 HW Mate 90 的验证样本，不得混入手机机型字典。
- 组合适配机型维持原物料显示名和已映射的同一机型码，不自动拆成两条物料。
- 用户已确认但总表尚未覆盖的 12、13、16 应能正常作为新机型使用，不能要求“先在总表存在才生成”。
- 模糊识别必须防止 Pro/Pro Max、S24/S24+、S25/S25U 等短名抢先匹配；先解析完整机型，再精确字典匹配。

## 4. 出镜壳普通/银框成对证据

以下都固定同一图案与 iP14 Pro，末两位始终为 57。地址均为总表实际 Excel 行号，C 为编码，D 为名称。

### 4.1 J7：A0 对应 AC

图案：Tsumtsum Series#J7 / Bear & Pals / CZ00252。

- 普通：`条码!C53587:D53587`，`C.K.CA.AP.J7.A057`。
- 银框：`条码!C53643:D53643`，`C.K.CA.AP.J7.AC57`。

结论：普通标识 A0，银框标识 AC，机型码都是 57。与此前完成样表 J7 的记录一致。

### 4.2 A3：00 对应 AA，首字符也变化

图案：Magic Bow Series#A3 / Fountain Bow / CZ00050。

- 普通：`条码!C43206:D43206`，`C.K.CA.AP.A3.0057`。
- 银框：`条码!C43262:D43262`，`C.K.CA.AP.A3.AA57`。

同系列下一图案 Magic Mirror Bow / CZ00051：普通 `条码!C43207` 为 `A057`，银框 `条码!C43263` 为 `BA57`。

结论：不能假设普通/银框只替换两位标识中的第二个字符，也不能强行让普通与银框共享同一个图案字母。

### 4.3 CC：A0 对应 AS

图案：菜菜系列 / 冰箱菜菜。

- 普通：`条码!C7778:D7778`，`C.K.CA.AP.CC.A057`。
- 银框：`条码!C7730:D7730`，`C.K.CA.AP.CC.AS57`。

结论：银框不是统一的 C，存在 S 等历史标识。

### 4.4 YC：AJ 对应 A0，A0 也可能是银框

图案：原创系列 / CZ00044。

- 普通：`条码!C32198:D32198`，`C.K.CA.AP.YC.AJ57`。
- 银框：`条码!C32226:D32226`，`C.K.CA.AP.YC.A057`。

结论：不能只看 A0、AC 或末段第二个字符就识别框型；必须读取明确名称/框型字段及具体图案映射。

## 5. 出片壳普通/银框成对证据

### 5.1 MO：普通 A0 对应银框 SR

图案：木偶奇遇记系列 / CZ00010。

- 普通：`条码!C31342:D31342`，`C.K.CA.AP.MO.A057`。
- 银框：`条码!C31398:D31398`，`C.K.CA.AP.MO.SR57`。

同系列 CZ00009 为 `0057 → 0S57`，分别在 `条码!C31341`、`C31397`。

结论：同一系列内不同图案也可能有不同历史标识对应关系。不能只给系列配置一个全局替换字母。

### 5.2 A1：0D 对应 0P

图案：Chip&Dale Series#A1 / Chip&Dale Play Instruments / CZ00070。

- 普通：`条码!C39512:D39512`，`C.K.CA.AP.A1.0D57`。
- 银框：`条码!C39568:D39568`，`C.K.CA.AP.A1.0P57`。

结论：普通款也不一定以 0 作为标识第二位，不能把所有普通款强制改成 A0/B0。

### 5.3 E4：0H 对应 0B，位于另一张工作表

图案：Blue Ocean Series#E4 / Starfish Shells / CZ00166。

- 普通：`出片壳!C10:D10`，`C.K.CA.AP.E4.0H57`。
- 银框：`出片壳!C67:D67`，`C.K.CA.AP.E4.0B57`。

同系列出镜壳的 Starfish Shells 产品码是 CZ00139，不能因为英文图案名称一样，把出镜壳的标识套给出片壳。

### 5.4 A6：历史上不仅末段变化，类别前缀也不同

图案：Cherry Bow Series#A6 / Silk Bow / CZ00115。

- 普通：`条码!C44115:D44115`，`C.K.CA.AP.A6.0C57`。
- 银框：`条码!C44171:D44171`，`C.K.CT.AP.A6.AT57`。

本次扫描发现 40 条出片壳银框记录使用 `C.K.CT.AP.A6.*`。这与用户提出的 CA 一体壳基础规则不一致，但不能未经确认就认定是错码或批量改成 CA。

处理：历史已有值只读保留；此规则域的新生成先标“历史前缀例外待确认”，支持人工核准后的规则版本。不要将 CT 推广为全部出片壳银框规则。

## 6. 正确的生成与复用策略

### 6.1 末段不是全局框型算法

在上述样本中，末两位确定为机型，前两位是按业务历史分配的图案/款式标识。总表无法支持“所有银框把 0 换成 C”或“首字母代表图案、第二字母恒代表框型”这类全局算法。

建议保存映射：

```text
企业 + 系列 + 规则域 + 具体产品类别 + 产品图案身份 + 框型/必要款式
  → 两位图案/款式标识 + 历史前缀信息 + 来源行 + 确认版本

品牌 + 手机产品范围 + 机型/已确认适配名
  → 两位机型码

最终物料编码
  = 已批准前缀 + 系列 + 两位图案/款式标识 + 两位机型码
```

此结构用作可配置规则，不扩大既有确定规则范围。其他配件仍使用其专属规则。

### 6.2 原有图案补新机型

以 J7/CZ00252 的银框补 iP15 Pro 为例：已验证该图案银框标识是 AC，iP15 Pro 的机型码是 61，候选物料码为 `C.K.CA.AP.J7.AC61`。必须先查总表及账本，若已存在同一 SKU 则复用而非重新分配；若同码已指向不同 SKU 则阻止生成。

这个示例解释拼接，不代表本轮实际创建或占用了该编码，也不表示该 SKU 当前未存在。

### 6.3 原系列新图案 / 全新系列

- 新普通图案按用户给出的 A0/B0/C0…提出候选，先查历史已使用标识及保留号；不重排已有 00、A0 等记录。
- 新银框若存在对应图案历史记录，直接复用其映射。
- 没有对应图案记录但存在经过业务确认的系列生成模板，可用该模板生成候选并确认。
- 没有任何批准模板时要求人工指定两位标识，做占用检查、记录理由和审批，再作为规则版本使用。不能从当前总表统计频率最高的字符擅自推定规则。
- CA 下出镜壳/出片壳使用不同映射键，但最终编码字符串没有单独写出具体类别，仍须在完整命名空间查重，不能各自分配相同尾段导致撞码。

### 6.4 自动映射冲突与异常

- 同一图案/框型在多个机型上的两位标识一致，可作为强历史佐证；冲突时逐条展示，不以最新行或多数票自动覆盖。
- 框型读取显式后缀；“银色片材”是材质，不能据此判银框。
- Y/B/T 等后缀按原规则保留，不在对照时一律删除；它们可能区别产品身份或印花版本。
- `.CT.`、礼盒 `.LH.` 等非当前批准模板的前缀单独标记，不用简单末两位规则自动生成完整码。

## 7. 69 码与物料编码的独立流程

69 码页面明确展示来源选择：

- 自定义内部号：按 `YYYYMM + 7 位流水`，从中央账本统一分配，跨电脑防重。
- 网站取得号码：打开用户指定的[中国商品信息服务平台](https://www.gds.org.cn/#/home/index)，用户完成平台操作后导入或填写结果，校验并保存来源。

未选来源不自动发号。华为和非华为都可选择任一方式，不能在背后根据品牌改选。已有来源与号码不会因切换页签或重新生成另一种编码被覆盖。

两个步骤分别绑定同一稳定物料行 ID，保存各自结果与状态。最后统一检查“物料编码通过 + 69 码通过 + 图档核对通过”，再允许 B 返回 A。

## 8. 本次核验限制

- 核验针对所提供的 260908 版本总表，不能宣称覆盖企业所有历史文件。
- 机型字典由用户确认，历史名称与款式映射由总表提供证据；两种依据分开记录。
- 42 项有总表佐证不代表对所有历史物料行做了无异常认证，也不代表另外 3 项不可用。
- 单元格内容按只读值检查，未执行宏、未重新计算或保存工作簿，未改变已有物料编码。
- 银框历史映射的事实已经明确；没有历史样本的新款式如何选择未用两位标识，仍需采用批准模板或人工确认，而不是声称找到了统一算法。

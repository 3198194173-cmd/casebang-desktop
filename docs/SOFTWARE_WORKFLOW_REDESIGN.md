# CASEBANG 软件主流程与页面重构

日期：2026-09-17  
目标：用“一份中央工作簿 + 一条共享记录”跑通两人闭环，去掉收发任务式的额外步骤。

## 1. 业务主线

三个现有功能是并列的上游建表入口，任意一个都会产生“新建表”：

- 新系列建表
- 系列补产品
- 产品补机型

之后只有一条闭环：

```text
上游生成新建表
  → 自动建立中央工作簿和共享记录
  → 下游在同一工作簿中完成物料码、69 码和图档核对
  → 将当前阶段改为“待上游审核”
  → 上游审核、合并物料总表
  → 同步钉钉在线表格并回读验证
```

不存在“发出文件 → 对方接收 → 下载副本 → 再上传”的业务步骤。

## 2. 功能分开，数据共享

登录时选择业务端：

- **上游建表**：只显示三个建表工具、基础数据和最终审核合并相关功能。
- **下游加工**：只显示新建表加工、物料码、69 码和图档核对功能。

上游不显示下游工具，下游不显示上游建表工具。这是产品界面与工作范围的分离，不是对工作簿编辑者的严格锁定。两个参与人仍可在 WPS 中编辑同一份在线工作簿，系统按实际操作人保留修订记录。

## 3. 共享工作簿记录

“待我处理”和“我发出的”完全取消。双方都看到同一条工作簿记录，记录只展示：

- 工作簿名称和系列。
- 建表人与加工人。
- 工作簿修订号和最后修改时间。
- 当前阶段。
- 在线工作簿入口（WPS 接入后）。

共享记录不承担“接收任务”或“下载工作簿”。用户只在阶段变化时选择新阶段并保存，中央服务记录操作人、记录版本，并向另一位参与人生成通知事件。

## 4. 阶段模型

1. **已建表，待下游加工**
2. **下游加工中**
3. **待上游审核**
4. **需要修改**
5. **审核通过，待合并**
6. **已合并完成**

阶段是工作簿项目的属性，不是某个人的收件状态。修改阶段时发通知；WPS 里的每次自动保存不都发通知，避免打扰。

## 5. 导航结构

所有账号可见：

- 工作台 → 业务总览
- 共享记录 → 工作簿记录
- 系统 → 系统设置

仅上游可见：

- 上游建表 → 新系列建表 / 系列补产品 / 产品补机型
- 资料与配置 → 基础数据 / AI 与接口

仅下游可见：

- 下游加工 → 新建表加工

不再使用“协同任务”、“建档任务”、“任务中心”作为主导航名称。

## 6. WPS 与版本

```text
上游生成 XLSX → CASEBANG 建立中央文件 V1
                    ↓
             A/B 打开同一 WPS 在线工作簿
                    ↓
        保存回调形成 V2、V3……
                    ↓
      阶段更新形成明确的业务节点版本
```

CASEBANG 管理文件真实来源、参与人、修订号、哈希、阶段和审计；WPS WebOffice 负责在线编辑体验。不允许用“每台电脑一份本机副本”作为正式同步方案。

## 7. 当前实现状态

已调整：

- 登录时选择上游/下游，导航只显示对应工具。
- 共享列表改为参与人共同可见的“工作簿记录”。
- 取消收件箱/发件箱查询和对应页签。
- 取消页面上的选接收人、接收任务、下载工作副本。
- 共享记录可更新当前阶段，服务端使用版本号防止相互覆盖，同时写入通知发件事件。

尚未完成：

- 三个上游生成页自动建立中央工作簿记录。
- WPS WebOffice 文件打开、授权、保存回调和修订固化。
- 事务发件箱的真实钉钉消息发送器。
- 图档核对证据、正式发号、审核差异、总表合并和在线表格回读。

## 8. 双账号验收

1. A 以“上游建表”登录，只看到三个建表工具；B 以“下游加工”登录，只看到加工工具。
2. A 生成一份小型新建表，系统自动建立唯一共享记录。
3. A/B 在“工作簿记录”看到完全相同的记录、修订号和阶段，页面没有待办/发出切换。
4. A/B 同时打开同一份 WPS 在线工作簿，任意一方修改后另一方可见，服务端形成新修订。
5. B 将阶段改为“待上游审核”，A 收到通知；A 审核后改为“审核通过，待合并”。
6. 整个过程中不选接收人、不点击接收、不下载和重新上传副本。

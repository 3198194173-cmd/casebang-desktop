# CASEBANG 共享工作簿：本地 WPS 编辑与提交修订项目文档

状态：本地代码已实施，待云端部署与双账号真实工作簿验收。更新日期：2026-09-24。

## 1. 结论与范围

将现有的“WPS WebOffice 在线编辑、自动回调保存”改为“下载中央最新版到本机 → 使用本地 WPS 编辑并在 WPS 中保存 → 在 CASEBANG 点击提交修订 → 上传中央并刷新工作簿记录”。上游建表、系列补产品、产品补机型、外部导入，以及下游编码加工后的人工检查，统一使用同一条本地编辑入口和同一条提交链路。

这是**显式提交**方案，不是本地 WPS 自动同步，也不是两人实时共同编辑。用户只在本地按 Ctrl+S，中央文件不会改变；只有 CASEBANG 确认提交成功后，才增加中央修订和时间轴事件。两人可轮流编辑；若同时打开旧版本，后提交者必须处理版本冲突，不得覆盖先提交者的修改。

本文中的“工作簿记录”指截图里的共享记录页；用户说的“提交到工作表激励”按“提交到工作簿记录”理解。工作簿记录下方现有“编辑时间轴”，需要继续保留并正确区分软件加工与本地手动提交。

本期不修改建表模板、编码算法、钉盘 PDF/AI 图档核验、物料总表合并规则，也不改变用户手动决定“完成并归档／作废”的方式。停止使用 WebOffice 不等于取消 WPS 开放平台的商业订阅，费用侧仍需在其控制台单独确认。

## 2. 已核对的现状与必须修正的问题

1. 上游建立共享工作簿时，软件已直接生成并上传中央修订 1；“导出本地副本”是独立备份，修改它不会同步中央。新入口必须从共享记录下载中央最新版，不能误用导出副本。
2. `CollaborationService.openWorkbook` 已能下载并用系统默认 `.xlsx` 程序打开文件，但当前以调用方传入的修订号命名缓存，实际下载接口始终取**中央最新修订**。若列表在下载前发生变化，文件名和内容可能不一致；同一路径也可能保留上次未提交的本地修改。因此不能直接拿它作为正式编辑会话。
3. `CollaborationService.saveWorkbookRevision` 已具备 64 MB 上限、SHA-256、直传或分块上传和预期版本参数；服务器会创建不可变的 `workbook_revisions` 新修订，并在版本不匹配时返回冲突。要在桌面主进程增加安全的“本地编辑会话 → 读取固定文件 → 提交”封装，不能由渲染进程任意传文件路径或字节冒充当前记录。
4. 工作簿记录页确实已有“编辑时间轴”，但服务端当前仅返回最近 12 条保存／建立事件；`weboffice-save` 被标为“手动修改”，普通 `save-workbook` 一律被标为“软件加工”。新的本地手动提交不能继续被误标为软件加工，且较早记录应能继续查看。
5. 下游现有“填写 69 码／物料编码并保存”已将结果直接写入中央新修订，然后可选调用 WebOffice 打开检查。若中央保存成功但打开网页失败，整个 IPC 调用仍可能报错，使人误以为加工未保存。新方案必须把“软件加工成功”和“打开本地编辑器”分为两个独立结果。
6. WebOffice 入口分散在工作簿记录、上游导出、系列补产品、下游加工页以及中央物料总表入口。需要统一盘点并替换可见入口，不能只改截图中的一个按钮。

主要代码位置：

- `src/renderer/src/features/collaboration/CollaborationTasksPage.tsx`：工作簿记录、状态操作、编辑时间轴。
- `src/renderer/src/features/tasks/ExportWorkspace.tsx`、`src/renderer/src/features/supplement/SupplementPage.tsx`：上游建立共享工作簿后打开在线编辑。
- `src/renderer/src/features/lifecycle/MaterialLifecyclePage.tsx` 与 `src/main/ipc/register-ipc-handlers.ts`：下游软件加工和保存后打开 WebOffice。
- `src/renderer/src/features/material-data/MaterialDataPage.tsx`：中央物料总表的在线编辑入口。
- `src/main/modules/collaboration/collaboration-service.ts`：下载、打开、上传修订能力。
- `collaboration-server/src/collaboration.ts`：修订、并发校验、时间轴摘要。
- `collaboration-server/src/weboffice.ts`：原在线编辑回调；迁移期间保留旧数据读取能力，但新流程不再调用。

## 3. 统一业务流程

### 3.1 上游建立和人工修改

1. 新系列建表／系列补产品／产品补机型照旧生成工作簿并上传，得到同一条 `workItemId` 的中央修订 1。外部导入共享表也得到同样的工作簿记录。
2. 发布结果显示“打开本地编辑”和“查看工作簿记录”，不再显示“WPS 在线编辑”。进入工作簿记录后也能执行同样操作。
3. 点击“打开本地编辑”时，软件先核对当前中央 `version`、`revision`，下载对应文件至**新建、独立**的本地编辑会话目录，记录会话所基于的修订和 SHA-256，再交给本机 WPS 打开。
4. 用户在 WPS 中编辑，并在 WPS 内保存。回到 CASEBANG，输入可选的修改说明，点击“提交本地修改”。软件检查文件稳定、确有内容变化、格式有效及中央版本未变化，再上传并建立修订 2、3……。
5. 提交成功后工作簿记录显示中央新修订、最后编辑人和时间；时间轴新增“本地手动修改”事件。若没有修改，则提示“与下载版本相同”，不上传、不产生空事件。

### 3.2 下游软件加工后的人工修改

1. 下游选择工作簿时始终分析中央最新版。69 码和物料编码仍按当前独立流程运行；点击“填写并保存”后，软件先建立一个“软件加工”中央修订，例如修订 2。
2. 软件加工成功后独立显示“中央修订 2 已保存”，再提供“打开本地 WPS 检查”操作。若保留“保存后自动打开”勾选项，它只能触发后置打开动作；打开失败不撤销或隐藏修订 2，也不提示“加工保存失败”。
3. 本地编辑会话必须基于**加工后的修订 2**，不能基于加工前的修订 1。用户可检查和修改表格，保存到本地，再点击“提交本地修改”。有变化才生成修订 3。
4. 工作簿记录时间轴按顺序出现“软件加工 · 修订 2”和“本地手动修改 · 修订 3”；如只检查未修改，不应额外生成修订。图档核验可以继续独立进行，不因本地 WPS 是否打开而阻塞。
5. 本地手动提交不等于“完成并归档”，也不自动把编码结果合并进中央物料总表；原有人工确认与合并节点保持独立。

### 3.3 同一份中央记录

所有入口只传递 `workItemId`，编辑与提交都落在这条记录的新修订上，不新建第二条工作簿记录。上游和下游以各自有权限的钉钉账号看到同一修订链、同一时间轴。`COMPLETED`／`CANCELLED` 的记录只读，不能开始新的可提交编辑会话；本地已有草稿仍保留供备份或人工处理。

## 4. 本地编辑会话设计

### 4.1 创建与身份

新建会话由 Electron 主进程维护，渲染进程只拿到不含任意路径权限的 `sessionId`、工作簿名、基础修订、基础版本和状态。会话元数据至少含 `workItemId`、当前登录用户 ID、`baseVersion`、`baseRevision`、`baseSha256`、安全目录内的实际文件路径、创建时间和最后提交结果。重新打开应用时，应能恢复未提交会话；退出登录或换账号后不得直接替其他账号提交。

建议路径：`app.getPath('userData')/collaboration-workbooks/<workItemId>/edit-sessions/<sessionId>/workbook.xlsx`。路径由主进程生成，不接受前端提供的任意磁盘路径；不要把外部导入源文件或“导出本地副本”当成这个路径。每次“开始新编辑”都建立独立目录，防止旧缓存被当作最新版。

### 4.2 精确取得基础修订

现有 `GET /work-items/:id/workbook` 只取最新文件，且可能发生“先看到修订 2、下载时已经是修订 3”的竞态。实施时优先提供按修订号读取的只读接口，并仅允许读取同一工作簿有权访问的修订；或在服务端下载响应中携带与文件同一事务选出的修订、版本和 SHA-256，客户端严格核对。不允许单凭 UI 列表里的旧修订号为新下载内容命名。

取得文件后验证大小、SHA-256、`.xlsx` 的 OOXML 结构及实际可打开性。普通图片、公式、样式、分表不经重建或重新导出；本地编辑对象就是中央原始 `.xlsx` 字节副本。

### 4.3 启动本地程序

“WPS 本地编辑”在本机有 WPS 时启动 WPS；若系统的 `.xlsx` 默认关联不是 WPS，允许在设置中指定或选择 WPS 安装路径。不要把 WPS 可执行文件路径写死。没有 WPS 时，可明确提示用户选择已安装的 Excel 兼容编辑器；界面文案应反映实际打开的程序，不能把系统默认 Excel 冒称 WPS。

软件负责建立会话和打开文件，不监听键盘、不伪造 Ctrl+S，也不因为 WPS 窗口关闭而自动上传。提交按钮旁固定提示：“请先在本地编辑器保存；仅点击提交后同步中央。”

### 4.4 提交前后本地文件的保护

点击提交时从固定会话文件制作一次只读快照，读取前后校验文件大小、修改时间或哈希在短时间内稳定；如 WPS 正在保存或文件无法读取，提示先完成保存并重试。上传的是该快照，不是上传过程中仍可能变化的活动文件。

无变化不上传。若上传后发现活动文件又发生变化，已上传快照仍算一次成功修订，但会话标记“本地仍有未提交改动”，不得显示为完全同步。提交失败、版本冲突或网络中断时绝不删除本地编辑稿；上传成功且服务器返回新修订后才标记该快照已同步。本地恢复副本可按明确的保留策略清理，未提交和冲突稿不得自动删除。

## 5. 并发、冲突、错误与权限

1. **必须乐观并发校验。** 上传携带会话的 `expectedVersion` 和 `expectedRevision`，服务器在写入前检查；不匹配返回 `409 version_conflict`。不得在冲突时自动改成“以中央最新版为基底”重传旧稿，也不得静默覆盖。
2. 冲突界面展示“本地稿基于修订 X，中央现为修订 Y”，提供“保留并打开本地稿”“打开/下载中央最新版”“稍后人工合并”。明确两人不能像 WebOffice 一样实时合并单元格。
3. 服务器是权限和状态的最终裁决者：只有该工作簿参与人（现有共享物料总表按既有例外规则）可提交；已完成／作废的普通记录拒绝新修订。前端按钮置灰只是辅助，不替代服务端检查。
4. 同一上传请求重试须保持幂等，不得因网络回执丢失写出两个相同修订。已有相同 SHA-256 的中央最新版应返回“无需重复提交”，不新增时间轴事件。
5. 网络断开时允许继续修改本地稿，但提交显示“待同步”，不宣称已经保存到中央。恢复网络后重试仍使用原基础版本；如期间中央已变化，则进入冲突处理。
6. 应校验提交文件仍为同一会话的 `.xlsx`、未超过现有 64 MB 限制，且 ZIP/OOXML 基本结构有效。不要把当前工作簿名、钉钉 Token 或本地路径当作可信的客户端授权凭据。

## 6. 时间轴与数据契约

时间轴需要反映**中央已确认的事件**，不是“打开编辑器”“本地 Ctrl+S”或上传进度。事件至少展示：类型、执行人、中央修订号、服务器时间；可选展示用户填写的修改说明。顺序以服务器事件时间／版本为准，不以本机时钟为准。

展示类型：

- “建立共享工作簿”：上游生成或外部导入后的首个修订。
- “软件加工”：下游编码写回等由软件生成的修订。
- “本地手动修改”：本地 WPS/Excel 稿经用户点击提交并由中央确认的新修订。
- 历史 `weboffice-save`：仍显示为“历史 WPS 在线修改”，保留追溯，不因停用 WebOffice 被删除或重标。

现有 `save-workbook` 同时承载软件加工和拟新增的本地手动提交，不能仅凭它的 action 分类。建议在上传元数据／事件 `payload` 中增加受控的 `editMethod: 'software' | 'local-manual'`（旧事件默认 `software`），并在事件摘要映射到客户端 `activity.kind`；同时从事件中返回 `revision` 和 `reason`。原有历史事件保持原值，无须重写旧修订。必要时将活动 API 改为按页读取；现有仅取最近 12 条，界面应显示“最近 12 条／查看更多”，不能让用户误以为更早记录不存在。

一次软件加工加一次本地手动提交必须是**两个修订、两条事件**。无改动打开与网络失败不是修订事件。状态变化如“完成并归档”若纳入时间轴，应另以业务状态事件标注，不能混称文件编辑。

## 7. 页面与入口改造

### 7.1 工作簿记录页

将每条进行中记录的“WPS 在线编辑”替换为“本地编辑”；进入会话后显示“打开本地稿”“提交本地修改”“修改说明”“本地是否已保存／待提交”“基础修订 X／中央修订 Y”。成功时原位更新修订和时间轴。冲突时保留本地稿并给出恢复入口。完成、作废记录仍保留只读时间轴。

### 7.2 上游结果页

建表上传成功后显示“中央修订 1 已建立”“本地编辑”“前往工作簿记录”。“导出本地副本”继续存在，但明确其与受控编辑会话不同；本地副本不自动回传。系列补产品、产品补机型以及外部导入入口使用相同组件／服务，不各自实现一套提交逻辑。

### 7.3 下游加工页

去掉 `openOnlineAfterSave` 的 WebOffice 调用和相关文案。编码保存成功后先呈现真实中央修订，再显示“打开本地 WPS 检查”与“前往工作簿记录”。用户修改后可在下游页或工作簿记录页提交同一会话；两处状态保持一致。若下游软件加工过程中另一个人已更新中央，继续使用现有版本冲突提示，先刷新分析，不把加工结果写到旧修订。

### 7.4 其他 WebOffice 入口

中央物料总表当前也有“WPS 在线编辑”。迁移时要么接入同一受控本地会话（保留其既有全组织共享权限规则），要么在本期明确关闭按钮并提供现有“同步中央最新版／上传本地更新”替代；不得保留一个会触发付费 WebOffice 的可见入口。全局检索 `openOnlineWorkbook`、`weboffice-session` 和中文“WPS 在线编辑／检查”，清理用户可达路径。

## 8. 建议的实施分解

1. **服务端契约**：确保下载返回与字节一致的修订／版本／摘要；上传元数据增加编辑方式标记；时间轴返回修订、说明及分页信息。保留原 `workbook_revisions` 与旧事件，保证旧桌面端在过渡期的兼容性。
2. **主进程会话服务**：建立和恢复会话、受控下载、本地启动、稳定快照、无变化检测、版本校验、提交和冲突保留。IPC 只接收 `sessionId` 与说明，主进程自行读取会话文件和当前登录身份。
3. **前端统一组件**：工作簿记录页先打通完整闭环，再复用至上游发布页、下游加工页和其他入口。提交期间禁止重复触发；上传成功后立即刷新中央记录。
4. **下游解耦**：把“软件加工保存”和“打开本地编辑”分成两个动作／两个错误结果；加工成功不能被后置打开失败覆盖。确保打开的文件基于刚生成的中央修订。
5. **迁移收尾**：关闭 WebOffice 新会话入口和服务端启用开关；保留历史事件、旧修订及必要的回滚能力。真实账号和带图片模板的 `.xlsx` 验收通过后再考虑移除 WebOffice 代码和数据库表。

## 9. 验收用例

1. 上游发布新表得到修订 1；本地 WPS 修改、Ctrl+S、提交后得到修订 2，同一 `workItemId`，对方刷新后能读到改动；时间轴准确显示人、时间、修订和“本地手动修改”。
2. 下游基于修订 2 生成 69 码／物料编码得到修订 3，时间轴显示“软件加工”；本地核查并修改后提交得到修订 4，显示“本地手动修改”；仅查看不改时不产生修订 4。
3. 软件加工已上传成功，但本机没有 WPS 或启动失败：界面仍显示加工成功与修订 3，可稍后重新打开本地编辑。
4. A、B 都从修订 1 开始编辑；A 先提交修订 2，B 的旧稿提交返回冲突，中央修订 2 不被覆盖，B 本地文件可重新打开。
5. 编辑中网络断开、WPS 正在写盘、工作簿损坏、超过 64 MB、重复点击提交、提交回执丢失后重试，均不能丢失本地稿或产生错误的重复修订。
6. 应用重启后能恢复未提交会话；换账号或权限失效时不能把前一账号的会话提交到中央。
7. 图片、公式、样式、多个业务分表在本地编辑和上传下载后保持可用；用真实上游模板和真实下游编码样本比较关键单元格、图片数量及工作表顺序。
8. 已完成／已作废记录的旧版本和时间轴仍可追溯；历史 WebOffice 编辑事件可读；所有可见的新编辑入口不再打开 WebOffice 页面。

## 10. 交付顺序与发布前检查

先完成工作簿记录页的端到端闭环，再接入上游与下游，最后清理 WebOffice 可见入口。测试至少包括服务端修订与冲突测试、主进程会话恢复／文件稳定性测试、时间轴分类测试、下游“保存成功但打开失败”回归测试，以及双账号真实 `.xlsx` 人工验收。

代码实施后，按项目已有脚本运行 `pnpm typecheck`、`pnpm test`、`pnpm build`，再由两台实际 Windows 机器验证本地 WPS 打开、保存、提交、对端刷新。发布顺序应是服务端先兼容新字段和旧客户端，再更新桌面端，验收通过后关闭 WebOffice 新会话；不要在服务端升级前让新桌面端发送服务器不认识的严格校验字段。

## 11. 实施状态与上线门槛

桌面端已增加按登录账号隔离的本地编辑会话、精确修订下载与 SHA-256 校验、应用重启后恢复、稳定文件快照、无修改跳过、显式提交、冲突保留本地稿，以及上游、下游和物料总表的统一入口。下游软件加工保存与本地打开已解耦。服务端已增加修订元数据、按修订号下载、编辑方式标记和可分页时间轴；原 WebOffice 历史事件仍可读。新版可见入口不再启动在线编辑。

本地编辑稿不再因提交成功就成为不可达的残留文件：提交后会话保留到用户在 CASEBANG 点击“已关闭文档，结束并清理”。结束操作只删除该会话的本地工作簿和会话元数据；有未提交改动时必须再次确认放弃，中央修订不受影响。检测到表格软件临时文件或文件仍在保存时拒绝清理。外部 WPS/Excel 关闭事件无法由当前 Electron 打开接口可靠捕获，因此“仅关闭外部文档即自动清理”未实现；用户必须在 CASEBANG 点击结束按钮。

默认使用 Windows 对 `.xlsx` 的关联程序打开。用户也可在本地编辑面板用系统文件选择框指定 WPS/Excel 的 `.exe` 路径，或恢复系统默认程序；界面不会把实际由 Excel 打开的文件冒称 WPS 编辑。

代码静态检查、自动化测试和构建通过；尚未在真实钉钉双账号、真实 WPS/Excel 和云端部署环境完成第 9 节人工验收。服务端应先于新桌面端部署。云端 WebOffice 开关、商业订阅和旧回调代码尚未清理或停用，应在验收通过后单独处理，不应把当前代码状态描述成云端已上线。

# 下游印刷图档一键 AI 核验实施规范（v2）

## 1. 范围与验收目标

本功能属于“新建表加工”的步骤 3，独立于 69 码和物料编码是否已填写。操作者为当前工作簿粘贴本系列钉盘目录链接，按真实目录选择产品类别及必要时的样本机型，系统只把该范围内的 PDF 与同工作簿“图片”分表配对。按一次“一键 AI 对比核验”后，逐行取得 PDF 图案与共享表截图的视觉判断、原因和错误；名称/编码相同不等于视觉通过。

不修改源 PDF、共享表、物料总表或钉盘目录。本阶段 AI 结论是辅助核验，不写回工作簿，也不自动将工作项改为完成。缺失证据、权限失败、歧义、模型不确定均不得显示“通过”。

## 2. 输入与目录选择

- 系列目录由工作簿绑定，不能硬编码为某个系列 URL。目录索引按当前登录人的授权读取；节点和版本必须从服务端索引验证，前端传入的 URL 不能直接作为下载地址。
- 类别来自系列根下实际子目录；不存在固定“必须有机型”规则。类别下直接放 PDF（如支架、充电宝）时直接选该类别；存在叶子机型目录时列出真实目录名，只有叶子目录直接包含 PDF 才可选。允许两种结构并存。
- PDF 筛选首先依赖 `parentId` 的严格树关系。旧索引缺 `parentId` 时，路径回退必须比较完整目录片段，不能用字符串包含；`17PRO` 不得匹配 `17PROMAX`。
- 当前目录没有 PDF、存在多个可能机型目录或类别不明确时展示准确的缺失/选择提示，不静默扩大范围。

## 3. 配对主键与去重

PDF 文件名中 `#BG00733#CHARACTERCIRCLE` 的产品编码是优先主键；支架/充电宝的产品编码前缀可以不同。产品编码完整归一化比较；图案名称大写归一化为辅助交叉检查。

同一类别与机型下，`一个产品编码 = 一个主对比行`。同编码多份 PDF 记录为同一行的版本/材质候选，不增加主行数，也不自动选取任意一份作为 AI 输入。若同编码只有一份 PDF，则直接使用。没有编码的 PDF 按文件 ID 单独列为“待定位”。

横向对比行按匹配到的图片分表顺序、Excel 行号排序；通常这与 BG 产品编码从小到大相同。钉盘返回顺序不得改变展示顺序。未匹配图片表的 PDF 放在已匹配行之后，再按产品编码自然排序，方便定位异常。

共享表只读取名称包含“图片”的分表。根据所选类别和行内条码/物料名筛选，例如“磁吸背盖”归可拆卸，“出镜壳/出片壳/出彩壳”归一体壳，支架、充电宝各归本类。产品编码精确匹配优先；编码与大写名称有一项冲突即标记冲突，绝不可仅凭名称撞上别的产品行。多条同码图片记录只有截图与名称一致时可归并，否则标为歧义。

## 4. 界面与操作

顶部只保留系列链接、类别、可选机型、目录索引统计，以及一键核验按钮。主体为单一横向对比表：`PDF 图案缩略图 | PDF 文件名 | 共享表截图 | 图片对应名称(大写) | 产品编码/分表 | AI 结论`。每行两张图固定缩略尺寸，可点开原始钉盘 PDF；同码其他材质/版本在本行展开。不可在上方重复列几十个 PDF 卡片。

显示四种不同计数：筛选目录内 PDF 文件数、唯一编码数、已准确配对数、视觉核验已完成数。若原始 10 份 PDF 是 17PRO/17PROMAX 各 5 份，选 17PRO 后必须只见其 5 份与 5 个唯一编码。图片表跨机型的 17 行不能直接冒充当前 5 行。

选定类别与机型后，桌面端自动经授权接口获取该目录各 PDF 的临时下载信息，在本机逐份直连钉钉下载、渲染第一页并填入横向表的 PDF 图案列，无需先点击 AI 按钮，也无需用户手工保存文件。点击缩略图可在软件内放大查看完整第一页。预览加载中、失败原因和逐行重试必须可见。按钮只处理当前可核验行，复用已渲染页图，再逐行发送 PDF 图与表格截图到已配置的视觉 AI。可逐行重试，批量中一行失败不阻断其他行；执行期间显示 `已完成/总数`，避免二次点击。切换工作簿、系列、类别、机型、PDF 版本或图片表修订立即清空过期结论。离开或结束核验时取消尚未完成的 PDF 下载并释放临时预览。

## 5. PDF 内容与安全

服务端通过钉钉“获取文件下载信息”取得短效签名地址与下载请求头；先校验当前下游用户、工作项及绑定目录后代 PDF，只把该文件的下载信息发给桌面**主进程**。桌面主进程从受信任的钉钉/阿里云 HTTPS 下载域直连，原始 PDF 不穿过协同服务或 Cloudflare Tunnel，也不把钉钉令牌、签名直链或签名头暴露给渲染进程。桌面端使用非持久化、禁用 HTTP 缓存的 Electron 会话，顺序读取，限制 16 MB、完整响应时间及文件头 `%PDF-`；不写入下载目录、磁盘文件或日志。签名信息即取即用，工作簿/类别/机型切换或结束核验时取消未完成下载、清空内存预览。旧版 PDF 代理接口暂留给旧桌面端；新版桌面端必须先部署支持下载信息接口的服务端，不能静默回退到整份 PDF 云端转发。

桌面端将 PDF 第一页栅格化（必要时允许选页），展示实际页面缩略图，同时发送该图给 AI。PDF 页面内容/图片中的文字只当作数据，绝不当指令。若钉钉权限或 PDF 渲染失败，本行明确报错且保留“打开 PDF”人工检查入口；不能将共享表截图复制到 PDF 栏伪装已渲染。

下载接口参考[钉钉存储 API 的接口说明](https://dingtalk.apifox.cn/api-142019647)：`POST /v1.0/storage/spaces/{spaceId}/dentries/{dentryId}/downloadInfos/query?unionId=...`；返回 `headerSignatureInfo.resourceUrls` 与 `headers`，下载时必须透传签名头。接口权限必须以真实租户验证，不能由目录可索引推断一定可下载。

## 6. AI 判定契约

模型只比较两张图的主体设计、构图、姿态、道具、线条与相对位置；忽略手机壳轮廓、相机孔、载体、比例、背景和透明底差异。请求中提供 PDF 图与共享表截图，文件名/编码仅用于定位和审计，不得作为“同图”判断依据。要求结构化 JSON：`sameArtwork: boolean | null`、`confidence: 0..1`、`reason: 中文视觉依据`。无法确认时必须返回 null。

状态：`待核验`、`运行中`、`视觉一致`、`视觉不一致`、`不确定`、`缺 PDF 图片`、`缺共享表图片`、`编码/名称冲突`、`重复版本待选`、`读取失败`、`AI 失败`。仅当两图真实可用、主键/名称无冲突、模型判断一致且达到配置阈值（初版 0.9）时显示“AI 视觉一致”；该状态仍不等于人工放行。展示模型、时间和简短理由；不输出可能带敏感信息的完整提示词/令牌。

## 7. 失败隔离与测试

后端不得向任意用户提供任意 dentry 下载凭证。授权范围是同一组织、当前用户拥有的工作簿与已绑定系列目录的后代 PDF。断网、签名过期、钉钉 403/500、超大文件、非 PDF 响应和 AI 超时均按行失败，不归为图案不一致。重试仅重新处理失败/不确定行，已过期的输入哈希必须重算。

至少覆盖：`17PRO` 对 `17PROMAX` 的严格隔离；类别直放 PDF；支架/充电宝无机型；同编码多材质一主行；BG 码/名称交叉冲突；共享表无截图；PDF 无权限；AI 错误 JSON/低置信度；切换选择后旧结论清空；按钮可一次处理全部合格行。前后端类型检查、单测、构建必须通过。真实钉钉下载和真实 AI 结果仍需在已授权租户做端到端验收。

## 8. 实施顺序

1. 修正目录树与去重配对的纯函数和测试。
2. 接入受控下载信息签发、桌面直连 PDF 读取与本地第一页渲染，验证安全边界和退出清理。
3. 接入双图视觉 AI 与批量调用，保留逐行结果。
4. 重排横向表格并进行空态、错误态、切换态测试。

# 物料建档协同接入准备

更新时间：2026-09-16。已有条件：Ubuntu 服务器、casebang.tech 域名、钉钉开发者权限。

## 1. 域名可以复用，但不覆盖已有程序

推荐新增 `collab.casebang.tech`，指向同一服务器，为它独立配置 HTTPS 和反向代理。已有 `https://casebang.tech/AI/index.html` 的应用、路由、证书配置和数据保持不变。新数据库和私有文件目录也独立管理。

备选是 `https://casebang.tech/material-api/` 路径；此方案必须先检查已有网站的路径匹配、登录回调和前端回退路由，避免请求被原应用接走。第一选择仍是独立子域名。尚未连接或修改用户服务器，不能假设当前已经使用 Nginx 或 Docker。

原理参考：[Nginx 基于域名选择虚拟服务](https://nginx.org/en/docs/http/request_processing.html)。HTTPS 需要覆盖新主机名的有效证书，不能假设现有证书包含它：[Nginx HTTPS 配置](https://nginx.org/en/docs/http/configuring_https_servers.html)。

请准备：DNS 管理权限、计划使用的测试子域名、当前网站由谁维护，以及现有部署方式（面板 / Docker / Nginx / 其他）。暂不需要发送服务器密码或 SSH 私钥。

## 2. 可先返回的服务器检查结果

以下命令只查看版本和资源，不安装软件、不修改配置：

```sh
lsb_release -ds
docker --version
docker compose version
free -h
df -h /
```

若提示 command not found，直接保留提示即可，不要为此立即安装或替换现有服务。回复检查结果前可隐藏主机名；不要粘贴环境变量、容器完整配置、密钥或数据库连接串。

后续部署前再确认：现有 80/443 入口、测试数据库独立账号、备份与恢复方式、证书续期、可用磁盘和访问控制。PostgreSQL 与私有工作簿存储不直接公开到互联网。当前仓库仅有迁移草案，尚无可直接投产的中央服务包。

## 3. 钉钉企业内部应用

由有权限的开发者创建独立测试应用，准备 CorpId、AppKey/Client ID、AgentId。AppSecret/Client Secret 仅保存在服务器的安全配置中，不写入源码、安装包、日志或聊天。应用基础信息位置参考：[钉钉官方端外登录示例](https://github.com/open-dingtalk/h5app-out-login-demo)。

- 两个同企业测试账号：建表人 A 和编码/图档处理人 B；都要在应用可见范围内，并实际登录软件后才进入收件人列表。
- 登录回调地址要等服务路由实现和 HTTPS 验证后再登记，不预先把尚未实现的路径视作可用。
- 根据真正采用的接口申请最小权限：登录身份、企业内消息、指定钉盘图档和在线表格。开发者权限不代表应用自动拥有全部文件的访问权。
- 先使用测试文件夹和测试在线表格，不让开发测试改动生产物料总表。
- 钉盘预览访问方式及在线表格接口能力要用真实账号验证；不能把“能打开网页”当作“接口可以读取所有图档”。不要求整包下载大型 PDF。

## 4. 业务验证资料

1. 最近的物料总表副本，用于核对现有物料编码和 69 码占用。
2. 用户已提供的完成表，以及一份未填编码的新建表测试副本。
3. 包含普通款、银框、苹果/三星/华为、未知机型或特殊品类的样例。
4. 一套小范围图档测试文件夹，保留英文名 / BG 编号与真实图案之间的对应关系；不下载整个大型图档库。
5. 在线物料表的测试副本、字段说明和可操作账号。
6. 明确新图案两位标识的分配边界、已有特殊银框映射、未覆盖类别规则和内部年月流水的历史起点；有疑点时停止正式发号，不猜测。

## 5. 安全的首轮联调范围

只做测试环境：两个账号登录 → A 明确选择 B 并确认交接 → B 接收对应版本 → B 退回说明或提交核验结果 → A 复核。任何真实通知或在线写入都应在用户明确启用的测试任务内进行。正式总表合并和生产同步留到后续验收，不随软件启动自动触发。

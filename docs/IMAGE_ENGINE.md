# 单张总图导入与裁图模块

## 已实现流程

1. 在任务向导第 2 步选择一张 PNG、JPG、WEBP、TIF 或 TIFF 产品排版总图。
2. 程序读取原图尺寸和方向，生成仅用于界面显示的缩略预览，不修改源文件。
3. 程序根据图片边缘估算背景色，自动寻找白底上的独立产品区域，并按从上到下、从左到右排列。
4. 第一项固定保留为“全系列主图”，不要求确认产品类型；其他候选区域可在界面中移动、缩放、增加、明显删除、改名和选择产品类别。若多个圆形产品被识别成一个宽区域，可选中后点击“细分识别”。
5. 程序会按外形、镜头区、外圈深浅和左下电量指示点给出产品类型初判、置信度与判断依据；低置信度结果必须人工确认。
6. 用户确认后选择保存位置。程序建立新的带时间戳目录，并从原始高清图导出 PNG；不会覆盖源图或已有文件。

## 使用边界

- 当前自动识别主要针对浅色或白色背景、产品之间留有间距的排版总图。
- 产品互相接触、阴影连接、复杂背景或装饰文字可能造成区域合并或遗漏，此时使用“添加区域”和拖动修正。
- 产品类别下拉清单由程序从当前导入的“命名-公式”动态收集；现有文件识别出 15 种产品类型，不再维护不完整的页面常量。
- 当前产品类型是本地规则初判：圆形浅色外圈倾向“磁吸气囊支架”，深灰外圈倾向“磁吸支架背盖”；左下约五个指示点倾向“CP002/MP16 磁吸充电宝”，没有连续深色厚边的竖向卡片倾向“推卡卡包”。
- 磁吸背盖和一体壳目前只能检测到手机及镜头区域，镜头框是否闭合仍需人工确认；CP002 与 MP16 也需人工确认。
- 区域设置默认调用项目独立的本地视觉模型，也可切换阿里云百炼备用。模型针对当前裁剪区域给出三组“英文名称 + 中文对应 + 判断理由”；系列通用名和已有重名会被过滤，用户选择后仍可手工修改，只有英文名称进入后续表格。
- 全系列主图是系列命名和后续表格写入的基准，界面不可删除，导出接口也会校验必须且只能有一张。

## 命令行验证

项目未全局安装 pnpm 时，先在 PowerShell 设置：

```powershell
$pnpm = "C:\Users\Administrator\.cache\codex-runtimes\codex-primary-runtime\dependencies\bin\fallback\pnpm.cmd"
```

分析一张真实总图并生成 JSON 报告和预览图：

```powershell
& $pnpm image analyze --source "C:\完整路径\总图.png" --report "C:\完整路径\分析结果.json" --preview "C:\完整路径\识别预览.webp"
```

确认或修改 JSON 中的 `crops` 后导出原图裁片：

```powershell
& $pnpm image export --source "C:\完整路径\总图.png" --plan "C:\完整路径\分析结果.json" --output "C:\完整路径\导出父目录"
```

运行回归测试和桌面生产构建：

```powershell
& $pnpm test
& $pnpm build
```

## 代码分层

- `src/shared/image-contracts.ts`：前后端共用的数据结构。
- `src/main/modules/image`：图片校验、区域检测、高清裁图和导出目录管理。
- `src/main/ipc` 与 `src/preload`：只暴露“分析图片”和“导出裁图”两个受控接口。
- `src/renderer/src/features/tasks/ImageCropWorkspace.tsx`：可视化裁图工作区。
- `src/cli/image-engine.ts`：无需打开桌面程序的命令行验证入口。

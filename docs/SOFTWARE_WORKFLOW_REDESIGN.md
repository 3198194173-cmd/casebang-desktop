# CASEBANG 软件主流程与页面重构

日期：2026-09-17  
目标：先统一业务逻辑、账号职责、文件流向和页面命名，再继续开发编码、核图与总表同步。

## 1. 唯一主流程

现有三个功能不是互相连续的三步，而是三种并列的上游建表入口：

- **新系列建表**：新系列裁图、命名、产品编码、生成与质检。
- **系列补产品**：在既有系列中增加产品或图案，复用历史系列与命名资料。
- **产品补机型**：为既有产品增加机型，依据物料总表匹配并生成新增记录。

任意一个入口完成后都产生一份“待建档工作簿”，然后进入同一个下游流程：

```text
新系列建表 ─┐
系列补产品 ─┼─→ 生成与质检通过 → 提交建档任务 → 建档处理 → 原建表人复核 → 合并总表 → 同步在线表格
产品补机型 ─┘
```

因此，界面不能再把“协同任务”和“物料建档”作为两个平级业务模块。协同只是任务传递机制，真正对用户有意义的下游入口只有一个：**建档任务**。

## 2. 两个账号的职责

### A：建表人

1. 从三个上游入口中选择一个完成建表。
2. 在生成与质检通过后点击“提交建档”。
3. 选择同企业的建档人 B。
4. 等待 B 完成编码和核图。
5. 接收 B 返回的新修订，查看差异。
6. 不通过时退回 B；通过后合并物料总表并同步钉钉在线表格。

### B：建档人

1. 在“建档任务”的“待我处理”中看到任务。
2. 接收任务并取得服务器保存的同一文件版本。
3. 完成物料编码与 69 码，两项先后不限。
4. 对照钉盘图档，逐项记录核对结论。
5. 在 Excel/WPS 修改工作簿后，将新修订上传服务器。
6. 所有必填项和图档核对通过后，提交给原建表人 A 复核。

账号属于整个软件，不属于某一个页面。登录后所有页面共用同一企业身份；退出登录也应全局生效。

登录前单选默认工作区：**上游建表**或**下游建档**。这个选择只决定登录后的默认首页和任务页签，不形成严格角色权限墙。两个参与账号都能进入上下游功能、查看自己参与的中央工作簿并编辑；系统重点记录操作者、版本和业务阶段。功能通过导航分区保持清晰，只有任务外的其他企业账号不能访问该项目。

## 3. 中央工作簿与版本流

```text
上游生成新建表
  → 系统自动存档为中央工作簿 V1
  → A/B 在软件内通过 WPS WebOffice 打开同一工作簿
  → 编辑内容实时同步，后台保存 V2、V3……
  → 提交审核时形成明确的业务节点版本
  → A 确认后由系统合并基础表和物料总表
```

用户不再执行下载、另存或重新上传；文件传输只存在于 CASEBANG 服务与在线编辑服务的后台。中央工作簿需要满足：

- 文件永久存储、版本号和业务状态由 CASEBANG 服务管理，WPS 只负责在线编辑。
- 每次存盘记录修改人、时间、文件哈希和连续修订号。
- “提交处理”“提交复核”“审核通过”形成清晰的业务节点版本，普通自动保存不挤满主时间线。
- A/B 都可以编辑同一个项目；系统按实际操作者记录修改，不以默认工作区阻止编辑。
- 审核页提供业务字段差异，不依赖二进制 XLSX 文件差异。
- 合并前重新校验工作表结构、公式、图片、编码和基础表版本。

## 4. 页面与导航

左侧导航只表达稳定业务入口：

- **工作台**
  - 业务总览
- **上游建表**
  - 新系列建表
  - 系列补产品
  - 产品补机型
- **任务中心**
  - 建档任务
- **资料与配置**
  - 基础数据
  - AI 与接口
- **系统**
  - 系统设置

不再在左侧同时出现“协同任务”和“物料建档”。旧工作簿手工导入只是测试与历史补录能力，应作为“建档任务”页面的次要按钮，不应成为主导航。

## 5. 建档任务页面

默认先显示任务列表，不先显示编码表单：

- **待我处理**：分配给当前账号的任务。
- **我发出的**：当前账号创建的任务。
- **待我复核**：B 已完成、等待 A 确认的任务。
- **已完成**：已合并或已同步的任务。

点开一项任务后，根据当前账号的职责显示不同操作。

建档人 B 的任务详情：

1. 接收并开始处理
2. 编码处理
3. 图档核对
4. 提交复核

建表人 A 的任务详情：

1. 查看结果
2. 差异复核
3. 合并总表
4. 同步在线表格

系统连接状态、钉钉 Stream、服务器地址和接口权限只放在“系统设置”，不能成为业务步骤页签。

## 6. 页面命名规则

页面名称使用“对象 + 动作”，不使用开发术语或过长说明：

- 表格编码 → **新系列建表**
- 原有系列补充新产品编码 → **系列补产品**
- 原有产品补充新机型 → **产品补机型**
- 协同任务 + 物料建档 → **建档任务**
- 物料编码预检 → **检查物料码**
- 69 码来源 → **选择69码来源**
- 提交交接 → **选择接收人**
- 接入状态 → 移至 **系统设置**

说明文字可以保留完整业务含义，但菜单和按钮必须简短。

## 7. 当前真实完成度

已经完成：

- 全软件钉钉登录；登录前选择默认上游/下游工作区。
- 上游与下游功能在导航和页面中分区，但不会阻止两个项目参与人共同查看、修改中央工作簿。
- A 手工导入工作簿并上传中央服务器。
- B 点击一次即可接收任务、自动建立本机工作副本并用 Excel/WPS 打开；这是接入在线编辑前的临时兼容路径。
- B 填写原因退回 A。
- 任务版本、组织边界、责任人权限和操作事件基础校验。

尚未完成：

- 三个上游生成完成页直接提交建档任务。
- WPS WebOffice 在线编辑与保存回调；A/B 修改同一中央工作簿并自动形成新修订。
- A 查看两版差异并复核。
- 正式物料码、69 码账本和并发发号。
- 钉盘图档检索、预览和核对证据。
- outbox 真实发送钉钉通知。
- 物料总表合并及钉钉在线表格写入、回读。

## 8. 下一轮开发顺序

1. 先用一份真实新建表验证 WPS WebOffice 对图片、公式、样式和多工作表的兼容性。
2. 把三个上游流程的生成结果自动存档为中央工作簿 V1。
3. 实现 WebOffice 文件信息、用户、权限、下载地址和保存回调，让 A/B 在线编辑同一工作簿。
4. 建立自动保存版本、业务节点版本和表格字段差异。
5. 接入物料码、69 码、图档核对和审核合并。
6. 最后接钉钉在线表格和通知；本机工作副本保留为故障应急导出，不再作为主流程。

## 9. 双账号互传验收

测试必须使用两个不同钉钉账号，推荐两台电脑；单机切换账号只能作为补充测试。

1. A 登录时默认选择“上游建表”，B 登录时默认选择“下游建档”；服务器成员表中存在两条不同用户记录。两人仍可切换工作区并进入同一项目。
2. A 完成一份小型测试工作簿并选择 B 提交。
3. B 的“待我处理”出现任务，打开在线中央工作簿。
4. B 修改一个指定单元格并保存；A 同时打开时能看到更新，服务器形成下一修订。
5. A 的“待我复核”出现同一任务，能看到该单元格的业务差异和修改人。
6. A 退回一次，B 修订后再次提交；任务始终只有一个，修订号递增。
7. A 最终通过后再进入测试总表合并；正式总表和在线表格在全流程通过前保持只读。

# 物料建档协同：第一批实现说明

更新：2026-09-17。需求来源：`MATERIAL_LIFECYCLE_PROJECT.md` 与 `MATERIAL_CODING_RULES_AUDIT.md`。

## 本批可用范围

原有三个业务流程是并列的“上游建表”入口，生成后进入一份双方共享的中央工作簿记录。下游只使用“新建表加工”；不再建立收件箱、发件箱或下载副本式交接。

1. 导入上游生成的 XLSX 新建表，不修改原文件。复制私有快照，核对复制前后 SHA-256，相同文件重复导入复用已有草稿。限 64 MB、2 万条业务行。
2. 按“物料名称 / 69码 / 物料编码”表头识别，不依赖固定工作表名或 dimension 范围。保留原行坐标、现有号码、类目、材质、价格及备注；缺名称的业务行、公式缓存和重复号码明确提示。辅助列不用于猜机型。未识别工作表列入提醒，不静默认定整本已处理。
3. 本机 SQLite 保存草稿、准备参数和版本事件。乐观版本检查阻止旧草稿覆盖。切换页面仍保留当前编辑，退出时提醒未保存内容；重启可读取已保存草稿。这不是中央号码账本。
4. 独立的 45 项机型字典，机型码保留两位。按已确认别名识别，不把未知新机型自动映射到相近名称。
5. 物料编码候选遵守 `C.K.{BG|CA}.{AP|SA|HW}.{系列}.{两位图案款式标识}{两位机型码}`。只覆盖已明确的片材与一体壳类别；其他类别和 CT 历史特殊情况保留并拦截，等待规则确认。
6. 普通款、银框及 Y 等后缀分别保留身份。两位标识仅来自本文件可核对的已有编码或手工候选，不把 AC 当作所有银框通用规则。相同图案跨类别不复用编码。候选有重复或与历史矛盾时必须处理。
7. 69 码来源独立选择内部年月流水或平台来源，含华为也不强制选择平台。当前仅存选择，不分配实际号码，不替换现有号码。校验位正确不证明已在平台登记。
8. 中央服务基础：独立 Fastify 服务、PostgreSQL 校验和迁移执行器、私有工作簿存储、存活/就绪探针和 Docker 部署配置已经实现，并已在腾讯云真实环境执行迁移和探针验收。覆盖企业、用户、任务版本、物料行、号码占用、事件和通知发件箱。
9. 钉钉 Stream 安全收件基础已经实现并在真实服务端保持在线：使用服务端 Client Secret 主动连接，事件先落库再确认，失败请求稍后重试。
10. 钉钉端外登录服务端闭环已经实现：一次性 state 和轮询凭据仅保存 SHA-256，授权码在服务端换取用户信息，再通过企业应用 token 将 unionId 映射到当前企业 userId；只有当前企业成员可建立 30 天可撤销会话。浏览器回调不携带桌面会话令牌。
11. Windows 桌面端已经接入登录轮询：从系统设置或物料建档页发起登录，在系统浏览器完成钉钉授权；桌面端只接收短期轮询结果，正式会话通过 Windows 安全存储加密保存。服务不可达时保留已验证账号供离线识别，退出登录即使断网也会清除本机会话。
12. 登录已提升为全软件账号基础。登录时选择上游或下游：上游只显示建表工具，下游只显示加工工具；双方都可查看同一份工作簿记录。
13. 共享列表已改为“工作簿记录”：中央服务按参与人查询，不再接收 inbox/sent 参数，不再在页面显示“待我处理”或“我发出的”。
14. 共享记录已支持修改当前阶段。服务端使用数据库行锁、期望版本和幂等请求键防止两端覆盖，并为另一参与人写入阶段变化通知事件。WPS 在线编辑入口和三阶段保存回调已部署，本机导入仅作为编码规则联调，不再是正式交接方案。
15. 上游生成流程的最终步骤已改为“建立共享工作簿”：软件在受控临时目录生成新建产品表并直接上传中央私有存储、建立修订 1，成功或失败后清理临时文件。用户不再需要先选择导出目录；“导出本地副本”仅作可选离线备份，重复建立相同文件复用同一记录。

## 尚未实现，界面不应宣称已接通

- 桌面端登录代码已完成自动化验证，但新安装包中的人工登录界面仍需验收；当前仍不包含任务业务写接口。
- WPS WebOffice 的在线编辑承载页、回调签名、文件权限和三阶段保存尚未接入。完整边界见 `docs/WPS_WEBOFFICE_INTEGRATION.md`。通知发件箱已经记录，但真实钉钉通知发送器尚未开放。
- 接收端的编码/图档核验记录，以及基于这些服务端证据“完成并返回原账号复核”的状态操作。
- 历史总表号码账本导入与核对、事务发号、正式写回 Excel。
- 钉盘 PDF 在线图案核验，以及图档权限、版本和证据绑定。
- 外部 Excel 修改监听、冲突合并、任务新版本发布。
- 总表合并、在线表格同步和回读核验。

本批不增加假的登录、模拟收件人或成功通知；没有中央账本时不允许正式发号。原上游业务仍正常使用，不把原有本地草稿自动提交给其他账号。

## 主要代码入口

- `src/shared/lifecycle-contracts.ts`：独立建档数据契约。
- `src/shared/material-model-dictionary.ts`：用户确认的机型码。
- `src/shared/material-coding.ts`：身份拆解、候选编码和校验。
- `src/shared/lifecycle-workflow.ts`：服务端流程守卫；actor 和 evidence 必须来自服务端可信记录，不得接收客户端布尔标志代替核验。
- `src/main/modules/lifecycle/`：快照导入、表头读取、本机数据库和受信任 IPC。
- `src/main/modules/collaboration/collaboration-auth-service.ts`：桌面端登录发起、轮询、会话校验、离线状态和退出登录。
- `src/main/modules/collaboration/collaboration-service.ts`：中央工作簿记录和阶段更新。
- `src/renderer/src/app/account-context.tsx`：全软件唯一账号状态；顶栏、设置和业务页面共用。
- `collaboration-server/src/collaboration.ts`：企业和业务角色边界内的成员、任务、私有工作簿传输接口。
- `src/renderer/src/features/lifecycle/MaterialLifecyclePage.tsx`：本机工作簿、物料预检、69码来源和接入准备。
- `collaboration-server/src/`：中央服务配置、迁移、私有存储、健康检查、钉钉 Stream 收件与钉钉 OAuth 登录。
- `collaboration-server/migrations/`：由中央服务在启动时按校验和、事务和互斥锁执行，不由桌面客户端运行。
- `compose.collaboration.yml` 与 `deploy/`：协同服务通过 Cloudflare Tunnel 使用独立入口 `https://collab.casebang.tech/`，不改变现有 `/AI/`；数据库不暴露公网，API 仅绑定服务器本机。
- `tests/lifecycle.test.ts`：机型、银框、冲突、导入缺项、SQLite 持久化及交接守卫测试。

## 下一批实施顺序

1. 服务器、同域名 `/collab/` HTTPS 入口、PostgreSQL 和钉钉 Stream 已完成真实环境基础验收，现有 `/AI/` 入口保持正常。
2. 登录迁移、精确回调、最小权限和一个真实企业账号已通过；下一步用新桌面构建人工验收，再加入第二个同企业测试账号。
3. 用第二个同企业账号登录，验证两端只显示各自工具，同时能看到同一条工作簿记录和阶段。
4. 上游生成完成页已接到中央工作簿建立接口，WPS WebOffice 在线编辑与三阶段保存回调已部署；单账号可退出后切换业务端测试完整主流程，双账号同一 `file_id` 的并行编辑作为后续验收。
5. 导入并核对历史总表，确定号段起点、标识分配范围、跨产品规则，再开放正式编码及写回。
6. 图档核对、外部 Excel 版本同步、总表合并和在线回读分别增加测试与权限验证。

## 开发验收要求

本批验证记录：桌面类型检查、自动化测试和生产构建已通过。真实服务器 PostgreSQL、私有存储、HTTPS 反代和钉钉 Stream 已通过探针；真实钉钉账号“卓志”已在 Windows 桌面端完成登录验收。全局账号、工作区分区、成员目录、自动工作副本和首段交接代码已实现，仍需部署后使用第二账号进行双机人工验收。应用版本保持 0.1.4，本轮未生成新安装包。

- 本机导入不能写源文件，未知项目不能漏掉；跨页编辑不能因切换业务流程而丢失。
- 同图案普通/银框不混标识，末两位机型码不可错位。
- 内部流水校验位偶然正确仍不改变来源；未知平台来源不得伪造登记状态。
- 正式服务必须在事务中重验企业、责任人、版本、号码占用，不能依赖前端预检。
- 通知失败不丢任务、不重复发号；同步成功须远端回读匹配后才能完成。
- 服务端迁移、钉钉权限、Windows 安装包实际运行和双机交接尚需单独验收；单元测试与构建通过不等于这些步骤已完成。
